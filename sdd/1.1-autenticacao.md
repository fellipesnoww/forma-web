# 1.1 — Autenticação e onboarding

## Escopo entregue

- `/login`, `/register` com formulário (React Hook Form + Zod)
- Login com Google via Google Identity Services (GSI), sem redirect — `idToken` enviado direto para `POST /auth/google`
- Onboarding pós-login (`/onboarding`, 3 passos) com redirecionamento condicionado a `profile.onboardingCompletedAt`
- Sessão: `POST /auth/refresh` automático via interceptor (em `shared/api/client.ts`, não em `features/auth`), `POST /auth/logout` limpa sessão
- `GET /auth/me` hidrata sessão no boot do app (`AuthProvider`)

## Decisões técnicas

- **Login com Apple não implementado** — mesma ressalva do roadmap: depende de fluxo nativo Sign in with Apple JS, fora de escopo para SPA web pura por ora.
- **Sem rota de callback OAuth dedicada** — GSI usa popup/One Tap com callback JS direto (`google.accounts.id.initialize({ callback })`), não redirect. O item do roadmap "callback OAuth Google" é atendido por esse callback, não por uma rota `/auth/google/callback`.
- **Onboarding "concluído" é local, não persistido no servidor** — `PATCH /profile` (que marcaria `onboardingCompletedAt`) ainda não existe no backend (ver pendências). O botão final grava `localStorage['forma.onboardingSeen']` só para não repetir o carrossel a cada login nesta sessão de navegador; a fonte de verdade real (`profile.onboardingCompletedAt` vindo de `/auth/me`) prevalece assim que o backend implementar o PATCH.

## Rotas

| Rota | Guard |
|---|---|
| `/login`, `/register` | pública (`AuthLayout`) |
| `/onboarding` | `RequireAuth` |

## Integrações de API consumidas

Todas **reais e funcionais** hoje (confirmado via artifact de referência da API, `base http://localhost:3333`):

- `POST /auth` (registro), `POST /auth/login`, `POST /auth/google`
- `POST /auth/refresh`, `POST /auth/logout`, `GET /auth/me`

`POST /auth/apple` não é chamado (feature não implementada).

## Como testar

1. Backend em `http://localhost:3333` (ver `roadmap-backend.md` — **arquivo perdido**, contrato confirmado apenas via artifact de API).
2. `npm run dev`, abrir `/register`, criar conta → deve cair em `/onboarding` → "Começar" → `/app`.
3. Deslogar e logar de novo com a mesma conta → deve pular onboarding e ir direto para `/app` **apenas** se `onboardingCompletedAt` estiver setado no servidor (hoje sempre `null`, então sempre reabre onboarding — esperado até 1.2 existir).
4. Guard: acessar `/app` sem sessão → redireciona para `/login`.

## Pendências

- Nenhuma persistência real de "onboarding concluído" até o backend expor `PATCH /profile`.
- Botão Google só aparece com `VITE_GOOGLE_CLIENT_ID` configurado.
